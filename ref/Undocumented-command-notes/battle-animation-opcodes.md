Opcode 0x18 (3 bytes: 0x18 param1 param2)  
It resets/reinitializes battle formation or menu state. $7E:0926 sits in a block of battle menu RAM ($7E:091C-0928: menu options, party member count, cursor position). The 0x18 0x00 0x80 command overwrites this region, resetting $7E:0926 to the formation's expected party count — which is always 3 in vanilla. The randomizer's actual party size gets clobbered. Params 0x00 0x80 likely mean: target=0 (all characters / start of range), mode=0x80 (full reset, bit 7 set).

Opcode 0x44 (2 bytes: 0x44 offset) — "set transfer destination from current target's screen position"  
Handler at $C2:3318 (entry 0x44 in the animation-command jump table at $C2:0D3D, right after 0x43 = "playback sequence for object's current sprite"). For the object this script instance controls (indexed via $66), it reads that object's *current battle target* (per-object field $40:0060,X — set by SetTarget / opcode 0xBB), maps it to the target's working data ($7E:003E,X) and pulls the target's on-screen X position / X-extent ($40:0032,X, $40:0036,X) to derive a centered coordinate. It then subtracts the operand byte (the `0x60` in `0x44 0x60` = 96 px), and writes the result into the active object's AMEM destination slots: $40:0040,X (dest X), $40:0042,X (dest, ≈ that >>1 + offset), $40:0044,X = $8000 (transfer/arch flag). Advances the script pointer by 2.

In other words, it's the `SHIFT_TYPE_TRANSFER` analogue of `SetAMEM40ToXYZCoords`: instead of an absolute or caster-relative coordinate, it computes the destination from wherever the *target* currently is, offset by the operand. It must be followed by a `MoveSpriteToCoords(shift_type=SHIFT_TYPE_TRANSFER, …)`, which consumes those AMEM $40/$42/$44 values. Omitting it (as happened while editing battle event 2 / "Belome swallows Mallow", animation block 0x3AA8F2 at `command_0x3AB93D`) leaves AMEM40 holding stale data, so the next transfer-move sends the sprite to a garbage off-screen position and the scene never resolves — battle turn loop hangs. Pattern in vanilla: `SetTarget(<who>)` → `0x44 <offset>` → `MoveSpriteToCoords(SHIFT_TYPE_TRANSFER, …)`.
